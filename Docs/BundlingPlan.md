# Bundling Plan

## Project target

The app is an Android mobile application built with React Native and Expo using a custom development build through EAS. The final application must run the full pipeline on the phone: video capture, preprocessing, model inference, pin-state detection, pin-hit ordering, optional car-path tracking, annotated video rendering, and playback/export.

The project specification requires the pipeline to run fully offline at inference time. The app must not send the video to a backend server, call a remote API, or depend on a network connection during inference.

## What gets bundled into the Android app

### 1. JavaScript / TypeScript bundle

Bundled by Metro and Expo into the Android app.

Contains:

- React Native screens
- Navigation
- State management
- Video capture UI logic
- Processing status UI
- Result playback UI
- Calls into native modules
- Lightweight metadata handling
- Configuration constants

The JS layer does not run the CV model directly. It coordinates the pipeline and calls native code for compute-heavy video processing.

### 2. Native Android layer

Bundled inside the Android project generated by Expo prebuild / EAS development build.

Contains:

- Kotlin or Java native modules exposed to React Native
- Android Camera / Media APIs when needed
- OpenCV Android code if using classical preprocessing/tracking
- TensorFlow Lite / ONNX Runtime Mobile / NCNN inference runtime
- Video decoding and frame extraction
- Frame-by-frame annotation logic
- Video encoding for the final annotated output

This layer is responsible for performance-sensitive operations because pure React Native JavaScript is not suitable for frame-by-frame CV inference and rendering.

### 3. ML model assets

Bundled as static Android assets.

Recommended format:

- `.tflite` model for TensorFlow Lite
- Optional `.txt` or `.json` label map
- Optional model metadata file
- Optional calibration/config file for thresholds

Example app asset layout:

```text
android/app/src/main/assets/
  models/
    pin_detector_float16.tflite
    labels.txt
    model_config.json
```

Recommended model type:

- Fine-tuned YOLOv8n / YOLO11n object detector exported to TensorFlow Lite
- Classes: `standing_pin`, `fallen_pin`, `car`
- Optional: one class `pin` plus rule-based fall-state classification, but explicit `standing_pin` / `fallen_pin` classes are easier to defend

The specification requires building your own model, fine-tuning a pretrained model, or using transfer learning. A completely off-the-shelf model without training/fine-tuning is not acceptable.

### 4. CV preprocessing and postprocessing code

Bundled in the native layer.

Contains:

- Video frame decoding
- Frame resizing to model input size
- Color conversion: camera frame/video frame to RGB or BGR as required
- Normalization
- Detector inference
- Non-max suppression if not included in model export
- Pin tracking across frames
- Fallen-state transition detection
- Hit-order assignment
- Car tracking
- Path-point smoothing
- Annotation rendering
- Final video encoding

### 5. Local storage

Uses Android local app storage.

Stores:

- Raw captured video
- Temporary extracted/processed frames if needed
- Annotated output video
- JSON result file containing events and summary

Example result JSON:

```json
{
  "elapsedMs": 13200,
  "pinsKnockedDown": 5,
  "pinEvents": [
    { "pinTrackId": 3, "order": 1, "timeMs": 1450 },
    { "pinTrackId": 1, "order": 2, "timeMs": 2200 }
  ],
  "carPath": [
    { "timeMs": 0, "x": 120, "y": 600 },
    { "timeMs": 100, "x": 132, "y": 590 }
  ]
}
```

## Processing flow inside the bundled app

```text
User records video
        ↓
Raw video saved locally
        ↓
React Native calls NativeProcessingModule.processVideo(videoUri)
        ↓
Native layer decodes frames
        ↓
Preprocessing prepares frames for model input
        ↓
TFLite / mobile inference detects pins and car
        ↓
Postprocessing tracks pins and car across frames
        ↓
Pin fall events are detected and ordered
        ↓
Car trajectory is estimated
        ↓
Annotated frames are rendered
        ↓
Annotated video is encoded and saved locally
        ↓
React Native displays result video + score summary
```

## Why a development build is required

Expo Go is not enough because this project requires native Android code and native ML/CV runtimes. A custom Expo development build is required so the app can include:

- TensorFlow Lite / ONNX Runtime / NCNN native libraries
- OpenCV Android if used
- Custom native modules
- Video decoding and encoding APIs
- Model files bundled into Android assets

## Recommended bundling architecture

Use this structure:

```text
app/
  src/
    screens/
      RecordScreen.tsx
      ProcessingScreen.tsx
      ResultScreen.tsx
    native/
      ProcessingModule.ts
    types/
      ProcessingResult.ts

android/
  app/src/main/assets/models/
    pin_detector_float16.tflite
    labels.txt
    model_config.json
  app/src/main/java/.../processing/
    ProcessingModule.kt
    VideoDecoder.kt
    FramePreprocessor.kt
    TFLiteDetector.kt
    PinTracker.kt
    CarTracker.kt
    AnnotatedVideoWriter.kt
```

## Recommended model bundling strategy

1. Train or fine-tune the model outside the mobile app on your laptop or cloud notebook.
2. Export the trained model to TFLite.
3. Test inference on sample frames locally.
4. Copy the `.tflite` file into Android assets.
5. Load it from assets in the native Android module.
6. Run inference fully offline.

## Important constraints to defend during discussion

- The app captures the demonstration video live.
- The video is processed on the phone.
- No server is used during inference.
- The model is trained/fine-tuned/transfer-learned, not purely off-the-shelf.
- The final output video is produced locally.
- Pin labels correspond to the order in which pins fall.
- The final screen shows elapsed time and total knocked-down pins.
- Optional path detection is implemented as car tracking across frames.
